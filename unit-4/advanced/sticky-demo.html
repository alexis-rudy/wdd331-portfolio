01 / Overview

Sticky is a meeting point between two positioning modes.

An element with position: sticky behaves like a normally positioned element until it reaches an offset threshold. It then holds its place in the viewport while its scroll container still has room for it.

Unlike a fixed element, a sticky element keeps its place in the document. That makes it useful for navigation, headings, filters, and context that should stay available without floating forever.

02 / Normal flow

Start with the layout you would build without sticky.

Sticky positioning works best when the surrounding layout already expresses the relationship between the side content and the main content. This demo uses a two-column grid: the navigation is one grid item and the article is the other.

The container matters

The sticky item is constrained by its nearest scrolling ancestor. As the article reaches the end of its grid area, the navigation moves away instead of overlapping the footer or leaving the page.

Two columns, one long article, and a navigation panel with a job to do.

03 / Offset and boundaries

A small offset creates a comfortable reading rhythm.

The declaration top: 6.5rem gives the table of contents a safe landing spot below the persistent site header. Without an offset, the browser has no threshold at which the sticky behavior should begin.

The same idea applies to section headings. Each anchor target includes a scroll margin so a link jump does not hide the heading behind the header. These small details make the interaction feel intentional rather than merely technically correct.

Give the browser room to work

A sticky element needs enough scrollable space in its containing block. Grid and flex alignment can also affect the available height, so inspect the parent whenever a sticky element appears not to move.

04 / Useful patterns

Use sticky to preserve context, not to decorate.

A sticky subheading can label a long list, a filter bar can remain available while results change, and a documentation menu can show where a reader is in a larger guide. Each pattern answers the same question: what information is useful while the user moves?

  • Keep the sticky surface visually distinct from scrolling content.
  • Use a clear offset when another header is already sticky.
  • Test narrow screens, where a side panel may become a compact row.
  • Check focus states and keyboard navigation after anchor jumps.

Good sticky UI reduces memory load: the reader does not have to scroll back just to recover context.

05 / Recap

One property, a lot of useful continuity.

This page is long enough to make scrolling observable, but every section still has a focused purpose. The header uses position: sticky at the top of the viewport, while the navigation uses its own offset inside the article layout.

Resize the window to see the layout become a single column. The navigation remains sticky, but its links wrap into a compact row so the content stays readable on smaller screens.
